# T1021.001 - RDP Detection

## Technique Overview

Remote Desktop Protocol is a legitimate remote administration mechanism commonly used in Windows environments. From an attacker perspective, RDP can be used for lateral movement when valid credentials are available and the target system allows remote desktop access.

From a defensive perspective, the SIEM should not treat every RDP logon as malicious. The relevant question is who authenticated, from where, against which host and what activity occurred after the session was established.

## Detection Objective

The objective of this detection is to identify behavior compatible with RDP-based lateral movement in a Windows Active Directory environment.

The detection focuses on a remote interactive logon followed by post-access activity from the authenticated user context.

## Lab Scenario

The scenario was executed in a controlled virtual laboratory composed of a Wazuh server, a domain controller, a Windows workstation and a Kali Linux host used as the attack simulation machine.

The target system was WS01, a Windows workstation joined to the `lab.local` domain. The remote access originated from the Kali host inside the isolated laboratory network.

## Telemetry Used

The detection uses the following telemetry sources:

| Source | Event ID | Purpose |
|---|---:|---|
| Windows Security | 4624 | Successful RDP logon |
| Windows Security | 4634 / 4647 | Session termination / logoff |
| Windows Security / Sysmon | 4688 / Sysmon Event ID 1 | Post-access process execution |
| Wazuh | 92653 | Native RDP-related detection |
| Wazuh | 100001 | RDP post-access contextual rule |
| Wazuh | 92052 / 67027 | Command or process execution indicator |

## Detection Hypothesis

If a user authenticates remotely through RDP and this activity is followed by command execution or administrative activity on the target host, then the sequence is compatible with RDP-based lateral movement.

This hypothesis is stronger than detecting the RDP logon alone because RDP can be part of legitimate administration. The post-access activity provides additional context for analyst triage.

## Wazuh Detection Logic

The detection is based on a contextual approach:

1. Native Wazuh rule `92653` identifies the RDP-related logon.
2. Rule `100001` extends the detection chain by filtering activity linked to the observed laboratory user.
3. Additional process execution alerts provide post-access evidence.

## Evidence Observed

The scenario generated an RDP-related authentication event on WS01 from the Kali host. The relevant Windows event was a successful logon with RDP context, mapped by Wazuh to rule `100001`.

The alert included the source address, target host, authenticated user context and MITRE ATT&CK mapping to `T1021.001`.

## Analyst Interpretation

A single RDP logon should not automatically be treated as malicious. However, an RDP logon from an unusual source followed by command execution or administrative activity should be investigated as potential lateral movement.

The analyst should review:

- source IP address
- target host
- authenticated account
- logon type
- process execution after access
- whether the activity matches normal administration patterns

## Limitations

This detection was validated in a controlled laboratory environment. In production, RDP activity may be common for administrators, helpdesk users or remote support tools.

Additional baselining would be required to distinguish legitimate RDP administration from suspicious lateral movement.
