# T1021.002 — SMB / PsExec-like Detection

This write-up explains the detection logic for the **SMB / PsExec-like lateral movement scenario**.

It covers three detection hypotheses:

| Hypothesis | Meaning |
|---|---|
| **H3** | NTLM network authentication from Kali to `DC01` |
| **H4** | Access to administrative shares such as `ADMIN$`, `C$` or `IPC$` |
| **H5** | Remote service creation compatible with PsExec-like execution |

The global hypothesis model is documented in [`detection-hypotheses.md`](detection-hypotheses.md), but this file is designed to be readable on its own.

---

## 1. Technique Overview

**SMB** and **Windows administrative shares** are legitimate components of Windows administration.

They are commonly used for:

- file sharing;
- remote administration;
- software deployment;
- backup operations;
- endpoint management;
- remote troubleshooting;
- domain administration.

However, the same mechanisms can be abused for lateral movement when an attacker has valid credentials or administrative privileges.

PsExec-like techniques usually rely on the following observable sequence:

```text
network logon → administrative share access → Service Control Manager interaction → service creation → process execution
```

This detection does not depend on a specific offensive tool name. It focuses on the behavior produced by PsExec-like or smbexec-style remote execution.

---

## 2. Detection Objective

The objective is to identify behavior compatible with SMB-based lateral movement and PsExec-like remote execution in a Windows Active Directory environment.

The detection focuses on the combination of:

- NTLM network authentication;
- privileged logon context;
- access to administrative shares;
- remote service creation;
- process execution on the target system.

A single event is not treated as definitive.

The detection becomes stronger when several related signals appear close in time on the same target host.

| Field | Value |

| Source host | `Kali-ATK01` |
| Source IP | `192.168.56.40` |
| Target host | `DC01` |
| Target IP | `192.168.56.20` |
| Domain | `lab.local` |
| Account type | Privileged domain account |
| Main technique | `T1021.002 — SMB/Windows Admin Shares` |
| Related technique | `T1569.002 — Service Execution` |
| Main hypotheses | `H3`, `H4`, `H5` |

The scenario was executed from `Kali-ATK01` against `DC01`.

The target is the domain controller, so the asset criticality is higher than in the RDP workstation scenario.

---

## 4. Execution Summary

The command used in the controlled lab followed this structure:

```bash
crackmapexec smb 192.168.56.20 -d LAB -u <privileged_user> -p '<PASSWORD>' -x 'whoami' --exec-method smbexec
```

All credentials in the public repository are placeholders.

The expected behavior is:

```text
authenticate over SMB → obtain privileged session → access administrative resources → create temporary service → execute command
```

# 6. H3 — SMB Authentication from Kali to DC01

## 6.1 What H3 Tries to Prove

**H3** tries to prove that `DC01` received network authentication from the controlled attacker host using NTLM.

In natural language:

> **If `DC01` records a Logon Type 3 authentication from `192.168.56.40` using NTLM, then the SIEM has an initial signal compatible with SMB-based lateral movement.**

## 6.2 Expected Indicators

| Field | Expected Value |
|---|---|
| `agent.name` | `DC01` |
| `data.win.system.eventID` | `4624` |
| `data.win.eventdata.logonType` | `3` |
| `data.win.eventdata.authenticationPackageName` | `NTLM` |
| `data.win.eventdata.ipAddress` | `192.168.56.40` |
| `data.win.eventdata.targetUserName` | `<privileged_user>` |
| `rule.id` | `100011` |
| `rule.mitre.id` | `T1021.002`, `T1550.002` |

## 6.3 Detection Value

H3 gives the analyst the first signal in the SMB chain:

```text
A remote host authenticated to DC01 over the network using NTLM.
```

This is useful because SMB/PsExec-like activity requires a network authentication step.

## 6.4 Limitation

H3 is weak if interpreted alone.

NTLM network logons are common in many Windows environments.

Possible legitimate causes:

- file share access;
- backup agents;
- software deployment;
- endpoint management tools;
- administrative scripts;
- remote inventory tools;
- legacy applications;
- printers or scanners.

Therefore, H3 should not be treated as final attribution.

---

# 7. H4 — Access to Administrative Shares

## 7.1 What H4 Tries to Prove

**H4** tries to prove that the authenticated remote session accessed administrative SMB resources.

In natural language:

> **If `DC01` records access to `ADMIN$`, `C$` or `IPC$` from the same source, then the SMB lateral movement hypothesis becomes stronger.**

## 7.2 Expected Indicators

| Field | Expected Value |
|---|---|
| `agent.name` | `DC01` |
| `data.win.system.eventID` | `5145` |
| `data.win.eventdata.shareName` | `ADMIN$`, `C$`, `IPC$` |
| `data.win.eventdata.ipAddress` | `192.168.56.40` |
| `rule.id` | `92218` or related administrative share rule |

## 7.3 Detection Value

H4 shows that the network logon was not only an authentication event. It interacted with administrative SMB resources.

This matters because PsExec-like execution often uses:

```text
ADMIN$ / C$ / IPC$ / \pipe\svcctl
```

## 7.4 Limitation

Administrative share access is not malicious by itself.

It can be legitimate when performed by:

- system administrators;
- backup platforms;
- EDR tools;
- deployment platforms;
- monitoring products;
- domain management scripts.

H4 becomes meaningful when combined with H3 and H5.

---

# 8. H5 — Remote Service Creation Compatible with PsExec-like Execution

## 8.1 What H5 Tries to Prove

**H5** tries to prove that remote execution occurred through service creation.

In natural language:

> **If, after NTLM authentication and administrative share access, `DC01` records a new service creation, then the sequence is compatible with PsExec-like remote execution.**

## 8.2 Expected Indicators

| Field | Expected Value |
|---|---|
| `agent.name` | `DC01` |
| `data.win.system.eventID` | `7045` |
| `data.win.system.providerName` | `Service Control Manager` |
| `data.win.eventdata.accountName` | `LocalSystem` |
| `data.win.eventdata.serviceName` | Random, temporary or tool-generated name |
| `data.win.eventdata.imagePath` | Suspicious command or payload path |
| `rule.id` | `100010`, `92307` or `92650` |
| `rule.mitre.id` | `T1021.002`, `T1569.002` |

## 8.3 Detection Value

H5 is the strongest part of the SMB/PsExec-like scenario.

The chain becomes:

```text
NTLM network logon → privileged session → administrative share access → remote service creation → process execution
```

This is much stronger than any individual event.

## 8.4 Limitation

Remote service creation may be legitimate in some environments.

Possible legitimate causes:

- endpoint management platforms;
- software deployment systems;
- backup products;
- security agents;
- remote administration tools;
- maintenance windows.

The analyst must inspect the service name, service path and source host before escalating.

## 9. Detection Logic

The detection is built as a layered chain.

## 9.1 Layer 1 — NTLM Network Logon

Relevant rule:

```text
100011
```

Relevant event:

```text
4624
```

Meaning:

```text
A remote host authenticated to DC01 over the network using NTLM.
```

Weakness:

```text
Common in Windows environments. Weak if isolated.
```

## 9.2 Layer 2 — Privileged Session

Relevant rule:

```text
100021
```

Relevant event:

```text
4672
```

Meaning:

```text
The authenticated account received special privileges.
```

Weakness:

```text
Administrators also generate 4672 during legitimate activity.
```

## 9.3 Layer 3 — Administrative Share Access

Relevant telemetry:

```text
5145
92218
```

Meaning:

```text
The remote session accessed administrative SMB resources.
```

Weakness:

```text
Administrative shares are used by legitimate tools.
```

## 9.4 Layer 4 — Remote Service Creation

Relevant rules:

```text
100010
92307
92650
```

Relevant event:

```text
7045
```

Meaning:

```text
A service was created on DC01, which is compatible with PsExec-like execution.
```

Weakness:

```text
Some legitimate tools also create services remotely.
```

## 10. Evidence Observed

The scenario generated a compact alert sequence on `DC01`.

Expected chain:

```text
100011 → 100021 → 92218 / 5145 → 100010 / 92307 / 92650 → 92052 / 67027
```

Observed evidence includes:

- Logon Type `3`;
- NTLM authentication;
- source IP `192.168.56.40`;
- privileged session;
- administrative share access;
- service creation;
- process execution after remote service creation.

---

## 11. Analyst Interpretation

A single NTLM network logon is weak.

A single privileged logon is also not enough.

Administrative share access may be legitimate.

Service creation can also be legitimate.

The detection becomes strong because these signals appear together:

```text
same target + same source + privileged account + SMB + administrative share access + service creation + process execution
```

In the controlled lab, this chain is compatible with SMB/PsExec-like lateral movement.

In production, the analyst must check whether the sequence matches approved administration.

---

## 12. Triage Questions

An analyst should ask:

1. Is the source IP an approved administrative host?
2. Is the account expected to administer `DC01`?
3. Was the logon NTLM or Kerberos?
4. Was there access to `ADMIN$`, `C$` or `IPC$`?
5. Was `\pipe\svcctl` or Service Control Manager interaction observed?
6. What service name was created?
7. What was the service `ImagePath`?
8. Did the service execute a command or payload?
9. Was the process execution expected?
10. Is there similar activity on other hosts?

---

## 13. False-Positive Considerations

Possible legitimate sources of similar telemetry:

| Source | Why it can look similar |
|---|---|
| Backup agents | May authenticate remotely and access administrative paths |
| Endpoint management platforms | May create services or execute commands remotely |
| Software deployment tools | May use SMB and service creation for installation |
| Remote administration scripts | May trigger Logon Type 3 and privileged sessions |
| Legacy administrative workflows | May rely on NTLM and administrative shares |

Recommended tuning:

- define known administrative hosts;
- allowlist expected deployment tools;
- monitor service names and service paths;
- baseline privileged account usage;
- correlate service creation with source IP;
- increase severity for service creation on domain controllers.

## 16. Limitations

This detection was validated in a controlled laboratory environment.

The lab does not include:

- normal administrative noise;
- backup traffic;
- endpoint management platforms;
- real software deployment systems;
- multiple administrators;
- long-term false-positive baselines.

Therefore, this rule chain should be considered:

```text
validated laboratory logic, not production-ready detection without tuning
```

---

## 17. Key Takeaway

The SMB/PsExec-like scenario is strong because it is not based on one alert.

The detection value comes from the sequence:

```text
NTLM network logon → privileged session → administrative shares → remote service creation → process execution
```

That sequence is much more meaningful than any individual event in isolation.
