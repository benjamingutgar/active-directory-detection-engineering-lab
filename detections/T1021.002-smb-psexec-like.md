# T1021.002 - SMB / PsExec-like Detection

## 1. Technique Overview

SMB and Windows administrative shares are legitimate components of Windows administration. They are commonly used for file sharing, remote administration, software deployment, endpoint management and maintenance tasks.

However, the same mechanisms can be abused for lateral movement when an attacker has valid credentials or administrative privileges.

PsExec-like techniques usually rely on several observable behaviors:

```text
network logon → administrative share access → Service Control Manager interaction → service creation → process execution
```

This detection does not rely on a specific offensive tool name. The objective is to detect the behavior generated by PsExec-like or smbexec-style remote execution.

## 2. Detection Objective

The objective is to identify behavior compatible with SMB-based lateral movement and PsExec-like remote execution in a Windows Active Directory environment.

The detection focuses on the combination of:

- NTLM network authentication,
- privileged logon context,
- access to administrative shares,
- remote service creation,
- process execution on the target system.

A single event is not treated as definitive. The detection becomes stronger when several related signals appear close in time on the same target system.

## 6. Detection Logic

The detection is based on a layered approach.

### Layer 1 — NTLM Network Logon

Rule `100011` identifies network authentication using NTLM.

Expected indicators:

| Field | Expected Value |
|---|---|
| `data.win.system.eventID` | `4624` |
| `data.win.eventdata.logonType` | `3` |
| `data.win.eventdata.authenticationPackageName` | `NTLM` |
| `data.win.eventdata.ipAddress` | `192.168.56.40` |
| `agent.name` | `DC01` |
| `rule.id` | `100011` |

Analyst meaning:

```text
A remote host authenticated to DC01 over the network using NTLM.
```

Limitation:

```text
This does not prove malicious activity by itself.
```

### Layer 2 — Special Privileges

Rule `100021` identifies special privileges assigned to a non-system account.

Expected indicators:

| Field | Expected Value |
|---|---|
| `data.win.system.eventID` | `4672` |
| `data.win.eventdata.subjectUserName` | Non-system / non-machine account |
| `data.win.eventdata.privilegeList` | Administrative privileges |
| `agent.name` | `DC01` |
| `rule.id` | `100021` |

Analyst meaning:

```text
The authenticated session has privileged capabilities.
```

Limitation:

```text
Administrators also generate 4672 during legitimate logons.
```

### Layer 3 — Administrative Share Access

Administrative share access is observed through Windows Event ID `5145` and native Wazuh rules such as `92218`.

Expected indicators:

| Field | Expected Value |
|---|---|
| `data.win.system.eventID` | `5145` |
| `data.win.eventdata.shareName` | `ADMIN$`, `C$`, `IPC$` |
| `data.win.eventdata.ipAddress` | `192.168.56.40` |
| `agent.name` | `DC01` |
| `rule.id` | `92218` or related Wazuh rule |

Analyst meaning:

```text
The remote authenticated session accessed administrative resources.
```

Limitation:

```text
Administrative shares can be used by legitimate administration tools.
```

### Layer 4 — Remote Service Creation

Rule `100010` identifies service creation compatible with PsExec-like behavior.

Expected indicators:

| Field | Expected Value |
|---|---|
| `data.win.system.eventID` | `7045` |
| `data.win.system.providerName` | `Service Control Manager` |
| `data.win.eventdata.accountName` | `LocalSystem` |
| `data.win.eventdata.serviceName` | Random or tool-generated value |
| `data.win.eventdata.imagePath` | Suspicious path or command payload |
| `agent.name` | `DC01` |
| `rule.id` | `100010` |
| `rule.mitre.id` | `T1021.002`, `T1569.002` |

Analyst meaning:

```text
A new service was created on the target host, which is consistent with PsExec-like remote execution.
```

Limitation:

```text
Some legitimate software deployment, backup or endpoint management tools may create services remotely.
```

## 7. Evidence Observed

The scenario generated a compact sequence of alerts on `DC01`.

Observed chain:

```text
100011 → 100021 → administrative share access → service creation → process execution
```

The evidence includes:

- Logon Type `3`,
- NTLM authentication,
- source IP `192.168.56.40`,
- privileged session,
- administrative access behavior,
- remote service creation,
- process creation after remote execution.

## 8. Analyst Interpretation

A single NTLM network logon is weak.

A single privileged logon is also not enough.

Administrative share access may be legitimate.

Service creation can also be legitimate in some environments.

The detection becomes strong because these signals appear together:

```text
same target + same source + privileged account + SMB + service creation + execution
```

In the controlled lab, this chain is compatible with SMB/PsExec-like lateral movement.

In production, the analyst should review whether the sequence matches approved administrative activity.

## 9. Triage Questions

An analyst should ask:

1. Is the source IP an approved administrative host?
2. Is the account expected to administer `DC01`?
3. Was the logon NTLM or Kerberos?
4. Was there access to `ADMIN$`, `C$` or `IPC$`?
5. Was `\pipe\svcctl` or Service Control Manager interaction observed?
6. What service name was created?
7. What was the service `ImagePath`?
8. Did the service execute a command or payload?
9. Was the process execution expected?
10. Is there similar activity on other hosts?

## 10. False-Positive Considerations

Possible legitimate sources of similar telemetry:

| Source | Why it can look similar |
|---|---|
| Backup agents | May authenticate remotely and access administrative paths |
| Endpoint management platforms | May create services or execute commands remotely |
| Software deployment tools | May use SMB and service creation for installation |
| Remote administration scripts | May trigger Logon Type 3 and privileged sessions |
| Legacy administrative workflows | May rely on NTLM and administrative shares |

The detection should be tuned with:

- known admin hosts,
- approved service names,
- expected management platforms,
- maintenance windows,
- privileged account baselines.

## 13. Limitations

This detection was validated in a controlled laboratory environment.

The lab does not include:

- normal administrative noise,
- real backup traffic,
- endpoint management tools,
- software deployment systems,
- multiple administrators,
- production baselines.

Therefore, this rule chain should be considered:

```text
validated laboratory logic, not production-ready detection without tuning
```

## 14. Key Takeaway

The SMB/PsExec-like scenario is strong because it is not based on one alert.

The detection value comes from the sequence:

```text
NTLM network logon → privileged session → administrative shares → remote service creation → process execution
```

That sequence is much more meaningful than any individual event in isolation.
