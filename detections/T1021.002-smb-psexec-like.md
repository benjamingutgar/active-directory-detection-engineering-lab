# T1021.002 - SMB / PsExec-like Detection

## Technique Overview

SMB and Windows administrative shares are legitimate components of Windows administration. However, they can also be abused for lateral movement when an attacker has valid credentials or administrative access.

PsExec-like techniques typically interact with administrative shares and the Service Control Manager to execute commands remotely by creating a temporary service on the target system.

From a defensive perspective, the strongest indicators are not only the SMB connection itself, but the combination of network logon, privileged context, administrative share access and service creation.

## Detection Objective

The objective of this detection is to identify behavior compatible with SMB-based lateral movement and PsExec-like remote execution in a Windows Active Directory environment.

The detection does not rely only on a specific offensive tool name. It focuses on the observable Windows events generated by remote administrative execution.

## Lab Scenario

The scenario was executed in a controlled virtual laboratory composed of a Wazuh server, a domain controller, a Windows workstation and a Kali Linux host used as the attack simulation machine.

The target system was DC01, the domain controller. The attack simulation generated SMB-based remote activity, NTLM authentication and remote service creation behavior compatible with PsExec-like execution.

## Telemetry Used

The detection uses the following telemetry sources:

| Source | Event ID | Purpose |
|---|---:|---|
| Windows Security | 4624 | Successful network logon |
| Windows Security | 4672 | Special privileges assigned to a new logon |
| Windows Security | 5145 | Detailed file share access |
| Windows System | 7045 | Service creation |
| Windows Security / Sysmon | 4688 / Sysmon Event ID 1 | Process execution |
| Wazuh | 100011 | NTLM network logon indicator |
| Wazuh | 100021 | Privileged session indicator |
| Wazuh | 100010 | Remote service creation indicator |

## Detection Hypothesis

If a remote host authenticates over the network using NTLM, accesses administrative resources and creates a service on the target system, then the sequence is compatible with SMB/PsExec-like lateral movement.

This hypothesis is stronger than detecting a single network logon because Logon Type 3 activity is common in Windows environments. The detection becomes more relevant when combined with privileged access and service creation.

## Wazuh Detection Logic

The detection is based on a layered approach:

1. Rule `100011` identifies NTLM network logon activity.
2. Rule `100021` identifies privileged logon context.
3. Rule `100010` identifies remote service creation based on Windows Event ID `7045`.
4. Native Wazuh rules may also identify administrative share access or suspicious command execution.

## Evidence Observed

The scenario generated a sequence of alerts involving NTLM network authentication, privileged access and remote service creation.

The most relevant evidence was the combination of Logon Type 3 authentication, special privileges and service creation on the target host.

## Analyst Interpretation

A single NTLM network logon is not enough to confirm malicious activity. However, when NTLM authentication appears together with privileged access and remote service creation, the analyst should treat the sequence as a strong lateral movement indicator.

The analyst should review:

- source IP address
- target host
- authenticated account
- whether the account is privileged
- administrative share access
- service name and image path
- process execution after service creation

## Limitations

This detection was validated in a controlled laboratory environment. In production, legitimate administration tools, software deployment systems, backup agents or endpoint management platforms may also create services remotely.

Additional allowlisting and baselining would be required before deploying this detection logic in a real environment.
